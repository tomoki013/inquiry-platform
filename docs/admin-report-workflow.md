# 通報対応とメール返信

## 動作

- Remeet の通報フォームでメールアドレスを任意入力できる。未入力でも通報を受け付け、管理画面は返信欄の代わりに運営メモを表示する。
- 新規通報に問い合わせスレッドを紐付け、アドレスがあれば受付メールを送る。送信失敗で通報を失わず、定期処理で再試行する。受付メールに通報対象の本文・画像は含めない。
- 通報画面で受付メール・返信・運営メモを確認し、対応内容をメール送信できる。対応操作自体では結果メールを自動送信しない。運営が本文を確認して送信する。
- 返信は RFC Message-ID、In-Reply-To、References と固定した件名を使用する。Resend の送信管理 UUID は Message-ID として扱わず、送信メール取得 API の message_id を保存する。取得できなかった ID は再照会する。
- 署名は送信時に全返信・通報受付メールへ自動挿入する。下書き・定型文適用は本文のみ。既存の標準署名を含む下書きも末尾から取り除く。署名設定未登録・空の場合は `髙木友喜 / Tomoki Takagi` の標準署名を使用する。

## コンテンツ操作と署名

Remeet の既存の Ed25519 検証を維持する。秘密鍵を Workers に置かない。

1. 管理画面で「コンテンツを削除」または「対応なしでクローズ」を選ぶ。
2. Admin Core が保存済みの通報対象を使い、非公開 Service Binding 経由で API に操作案を作らせる。
3. Mac の署名サービスが、既存のキーチェーン鍵で正確な payload を署名する。
4. API が署名・操作案との一致・有効期限・manifest revision を検証して公開する。公開が成功してから Admin Core が通報の状態と履歴を更新する。

運営 Mac では `io.tmkch.remeet-moderation-signer` の LaunchAgent を登録済み。ログイン時に自動起動する。手動で起動する場合は次を実行する（常駐サービスとの二重起動はしない）。

```sh
pnpm --filter @tomokichi/api moderation serve
```

`127.0.0.1:47831` のみで待ち受け、`https://admin.tmkch.io` の Origin のみ許可する。ブラウザが求めた場合はローカルネットワークへの接続を許可する。ローカル開発時のみ `REMEET_ADMIN_ORIGIN` で使用する Origin を指定する。サービス終了後は署名を必要とする操作ができない。

複数の管理操作が競合した場合、古い revision の公開を拒否する。Admin Core も遅れて返った古い完了結果で新しい状態を上書きしない。公開後に管理画面への応答が失われた場合は同じ操作を再試行できる。

「対応なし」は、その通報の ID の SHA-256 digest を署名済み `dismissedReports` に追加する。アプリは検証済みの情報だけを使い、その通報による端末内の非表示を解除する。他の未解決通報がある場合は非表示を維持する。既存の有効な削除指示があるコンテンツはこの操作で復元しない。物理削除済みの iCloud コンテンツを復元する機能ではない。

## 互換性と確認範囲

- メールアドレスと dismissedReports は追加の任意フィールド。旧アプリからの通報や既存の署名済み manifest は引き続き受け付ける。
- アプリが対応情報を次に正常取得した時点で削除・非表示解除を反映する。オフライン端末に即座に反映されるものではない。
- 旧版で行った通報には端末内の通報 ID 対応表がないため、自動の非表示解除はできない。旧通報のメールアドレスも推測・補完しない。
- 既存通報には新しい問い合わせスレッドを自動遡及作成しない。既存の匿名通報にメール返信はできない。
- ローカルの D1 テストで署名改ざん拒否、競合拒否、削除・クローズ、公開失敗時の状態維持を確認。メールテストは fake provider を使用する。
- 管理画面は fixture データで表示確認。iOS は Simulator の通報・manifest・tombstone 関連テストを実施。実機 iCloud を通したコンテンツ削除は未検証。実メールの往復確認は末尾の記録を参照。

### 投稿者ごとの通報履歴

管理画面の通報対象に、同じアプリ内の `author_ref_hash` ごとの通報件数、通報者ID数、対応あり件数、直近10件へのリンクを表示する。クローズ済みも集計に残し、再送された同一通報は既存の受付重複排除により加算しない。本文や証拠を複製せず、既存の `reports` を参照する。0007 は検索用インデックスのみを追加する。

これはアプリ申告の仮名IDによる集計であり、実名・本人確認済みアカウント・違反確定数ではない。投稿者IDのない旧コンテンツや Remeet の Wish は不明として表示し、不明同士を同じ人として集計しない。「対応あり」は現在の対応済み状態または削除等の対応結果がある通報を数える。

送信メールは light/dark の color-scheme 宣言と暗色の本文・署名配色を持つ。HTMLを独自変換するメールクライアントでは表示が異なるため、実際の受信アプリで最終確認する。過去に送信済みのメールは変わらない。
